# 凡人修仙 MUD 元婴初期扩展设计

## 1. 设计结论

本轮目标固定为：

- 在现有“筑基初期可玩”版本基础上，把游戏推进到“元婴初期可完整到达”。
- 路线采用：
  - 主路径为主，身份线补摘要
  - 原创角色主路径，借原著时代节点
  - 长线重度版
- 世界继续保持“共享世界修仙 MUD”定位，不改成韩立单机剧情服。

本轮不追求元婴期全阶段完工，只交付：

- `筑基初期 -> 筑基中期 -> 筑基后期 -> 结丹初期 -> 结丹中期 -> 结丹后期 -> 元婴初期`

其中：

- `结丹准备` 与 `凝婴准备` 不作为独立境界名，而作为阶段标签与突破条件存在。

## 2. 产品定位

### 2.1 玩家身份

- 玩家继续是原创角色，不是韩立本人。
- 韩立、乱星海、虚天殿、古修遗迹等内容继续作为时代背景、世界节点、传闻与任务锚点存在。
- 玩家路径是在同一时代世界中经历这些节点，而不是复演韩立主线。

### 2.2 版本体验目标

本轮成品应同时满足：

- 一条完整主路径可从现有筑基版本一路推进到元婴初期。
- 散修 / 七玄门 / 黄枫谷 / 灵兽山在中后期仍然有存在感。
- 中后期仍以文本世界、命令、板帖、风声、任务、材料循环为核心，不退化成纯面板刷数值。

### 2.3 非目标

本轮不做：

- 元婴中期及以上内容
- 全门派同深度中后期内容
- 完整大型服级事件调度系统
- 全新战斗系统重写
- WebSocket / Telnet / FluffOS 改造

## 3. 核心玩法结构

从筑基初期到元婴初期，玩家成长由五条并行成长轴驱动：

### 3.1 境界轴

- `筑基初期`
- `筑基中期`
- `筑基后期`
- `结丹初期`
- `结丹中期`
- `结丹后期`
- `元婴初期`

说明：

- `结丹准备` 与 `凝婴准备` 用 `stage_label + flags` 表示。
- `breakthrough` 继续是唯一突破动作，但不再只看修为值。

### 3.2 主路径轴

主路径负责提供：

- 新区域解锁
- 新导师/NPC
- 新敌对目标
- 新丹药与丹方线索
- 新突破条件提示
- 新时代节点与关键事件

主路径不直接替代全部成长，不应让玩家只跑剧情就无条件到达元婴初期。

### 3.3 营生与材料轴

中后期长期循环固定包括：

- 采药炼丹
- 海猎采珠
- 遗迹与洞府采材
- 门派事务换资源
- 坊市委托与跑商
- 高风险区域采集与掉落

材料链必须从筑基中后期开始显著加厚。

### 3.4 身份轴

保留四条身份线：

- 散修
- 七玄门
- 黄枫谷
- 灵兽山

这条轴主要提供：

- 中后期事务入口
- 材料获取便利
- 丹方/术法/导师入口
- 身份资历门槛
- 称号与阶段摘要

### 3.5 认知轴

下列系统在中后期必须继续承担信息经济作用：

- `help`
- `codex`
- `rumor`
- `board`
- `rank`

玩家应通过文本线索理解下一阶段目标，而不是只靠界面提示箭头。

## 4. 阶段拆分

### 4.1 阶段 A：筑基扩张期

目标：

- 从 `筑基初期` 推进到 `筑基中期/筑基后期`

内容重点：

- 外海中层区域
- 古修洞府与残岛群
- 高阶采材点
- 更高阶筑基丹药与术法入口

身份推进：

- 散修开放外海游历与古洞探残
- 黄枫谷/灵兽山开放结丹前置事务

### 4.2 阶段 B：结丹准备期

目标：

- 从 `筑基后期` 进入 `结丹准备`

结丹准备固定拆成三条并行条件：

- 修为与丹火/气海稳定
- 结丹关键材料
- 身份资历或世界见闻

内容重点：

- 高风险秘境
- 高阶妖兽猎场
- 宗门炼丹/外务节点
- rumor 与 board 对结丹链的明确指引

### 4.3 阶段 C：结丹期

目标：

- `结丹初期 -> 结丹中期 -> 结丹后期`

内容重点：

- 乱星海更深区域
- 古修遗迹
- 结丹级敌对目标
- 结丹级法术、材料、丹药与宝物

身份推进：

- 门派路线获得效率优势
- 散修路线保持可玩但更依赖公共任务、坊市与高风险区域

### 4.4 阶段 D：凝婴与元婴初期

目标：

- 进入 `凝婴准备`
- 最终突破到 `元婴初期`

凝婴准备固定拆成三条并行条件：

- 神识与气海圆满
- 凝婴级关键灵物齐备
- 时代见闻或世界事件参与达标

内容重点：

- 高风险高收益区域
- 元婴前关键古修遗迹
- 世界 rumour/板帖/NPC 旧闻全面指向最终目标

## 5. 区域与章节节点

### 5.1 区域组织原则

- 保留现有：
  - 七玄门
  - 嘉元城
  - 太南
  - 黄枫谷
  - 天南港
  - 乱星海
  - 虚天殿
- 这些区域继续承担：
  - 前中期体验
  - 中后期 rumor / board / 工作 / 身份事务枢纽
- 本轮新增区域主要服务：
  - 筑基中后期
  - 结丹准备
  - 结丹期
  - 凝婴与元婴前高风险体验

### 5.2 主路径章节节点

主路径建议组织为：

1. 筑基稳固
2. 外海见闻
3. 结丹之门
4. 结丹准备
5. 结丹成功
6. 结丹后游历
7. 凝婴前夜
8. 元婴初成

### 5.3 建议新增区域类别

- 乱星海外海中层
- 古修洞府群
- 残殿群
- 高阶灵脉/火脉/冰窟/雷泽
- 凝婴相关高风险区域
- 中后期宗门/坊市服务点

### 5.4 内容量基线

本轮建议最低新增基线：

- 场景：`60-90`
- NPC：`45-70`
- 敌对目标：`50-80`
- 任务：`35-55`
- 工作/风声/公共事务：`25+`
- 物品/材料/丹药/宝物：`120-180`
- 丹方/关键配方：`20-35`
- 法术/高阶技能条目：`18-30`
- 手册/年历/传闻条目：`180-260`

## 6. 系统设计

### 6.1 境界模型

继续沿用现有 `realm_stage + realm_name + exp + next_breakthrough_exp`。

境界表扩展为：

0. `凡躯`
1. `炼气一层`
2. `炼气二层`
3. `炼气三层`
4. `炼气中期`
5. `炼气后期`
6. `筑基初期`
7. `筑基中期`
8. `筑基后期`
9. `结丹初期`
10. `结丹中期`
11. `结丹后期`
12. `元婴初期`

### 6.2 突破规则

`breakthrough` 保留，但条件分层：

- `筑基中期/后期`
  - 修为
  - 气海稳固
  - 基础材料
- `结丹初期`
  - 修为
  - 金丹准备度
  - 结丹主材
  - 身份/阅历
- `结丹中期/后期`
  - 修为
  - 少量进阶材料
  - 中长期积累
- `元婴初期`
  - 修为
  - 凝婴准备度
  - 凝婴主材
  - 世界见闻/阶段事件

### 6.3 状态承载

继续使用已有 JSON 状态块与 flags，不新增独立大表：

- `flags_json`
- `profession_json`
- `skills_json`
- `spells_json`
- `recipes_json`
- `codex_json`

新增中后期状态以这些方式承载：

- `gold_core_preparation`
- `nascent_soul_preparation`
- `gold_core_material_ready`
- `nascent_soul_material_ready`
- `major_world_witness`

字段命名可以在实现时再收敛，但语义必须稳定。

### 6.4 材料与丹药

本轮至少新增两套主链：

- `结丹链`
- `凝婴链`

每套必须包含：

- 主丹药
- 辅助丹药
- 主材
- 副材
- 稀有灵物
- 至少部分材料的多来源获取

炼丹系统继续采用现有配方驱动方式，不做自由试配。

### 6.5 任务、工作与风声

中后期内容按三层组织：

- `主线任务`
  - 解锁章节、区域、导师、关键材料来源
- `公众任务 / rumor / work`
  - 稳定产出材料、灵石、贡献、见闻
- `门派事务`
  - 提供身份推进和特定资源入口

### 6.6 战斗与掉落

不重写战斗内核，但扩充掉落层级：

- 筑基中后期敌人：结丹前材料
- 结丹期敌人：结丹后成长物与凝婴前置物
- 高风险区域敌人：凝婴主材或关键碎片

### 6.7 帮助与手册

新增帮助主题至少包括：

- `help core_dan`
- `help nascent_soul`
- `help map_outer_sea`
- `help map_core_ruins`

并同步新增对应 `codex` / rumor / 年历条目。

## 7. 客户端与协议方向

继续沿用当前技术路线：

- `Vue3`
- `protobuf over HTTP`
- `短轮询`
- `命令优先`

原则：

- 不新增高频 overlay 依赖
- 中后期帮助、rumor、board、工作、身份、突破提示继续走主文本流和字符板
- 新增境界与准备状态必须能进入现有终端式主界面

必要协议增量仅限：

- PlayerSnapshot 新阶段信息
- SceneSnapshot 新区域/服务标签
- StructuredPanel 新帮助与中后期摘要承载

## 8. 交付顺序

### 8.1 第一段：境界骨架先行

- 扩 realm stage
- 扩突破规则
- 扩结丹/凝婴材料与状态承载
- 扩帮助和世界包 schema

### 8.2 第二段：主路径直通

- 先补一条 `筑基后期 -> 结丹 -> 元婴初期` 完整主路径
- 让一条路线稳定玩通

### 8.3 第三段：生态加厚

- 补散修/门派摘要
- 补 rumor / work / board / codex / help / rank 的中后期内容
- 让它成为长线重度版而不是单通路线

## 9. 风险与约束

### 9.1 主要风险

- 只有境界上限，没有内容密度
- 主路径过强，身份线沦为装饰
- 材料链过厚，玩家像在查表
- 一次摊太大，最后留下半成品

### 9.2 风险控制

- 每个大阶段必须同步补：
  - 区域
  - 敌对目标
  - 材料来源
  - 帮助/手册
- 主路径负责解锁，身份线负责效率与资源入口
- 每个阶段只突出 `2-3` 个关键目标材料
- 严格按“骨架 -> 主路径 -> 生态”推进

## 10. 测试与验收

### 10.1 自动化

保留现有基础烟测，并新增中后期纵切面验证。

基础必跑：

- `node scripts/build_mud_world.mjs`
- `npm --prefix client test -- --run`
- `npm --prefix client run build`
- `wsl bash -lc "cd /mnt/c/Work/Projects/server && ./build-wsl-main/scripts/mud_smoke"`

### 10.2 基础烟测继续覆盖

- 建角与恢复
- `help`
- `commands`
- `rumor`
- `work`
- `board/read/post/discard`
- `codex`

### 10.3 新增中后期纵切面

至少覆盖：

- 筑基后期准备条件
- 结丹准备链至少一条
- 结丹突破
- 元婴前准备线索可见

完整“从零到元婴初期”的全自动烟测可以后置，但阶段性烟测必须先建立。

### 10.4 最终验收

本轮完成标准：

- 玩家仍是原创角色
- 共享世界修仙 MUD 定位不变
- 从现有筑基版本可以一路推进到元婴初期
- 中后期推进依赖主路径、风声、工作、身份事务、丹药材料链与高风险区域，不是只刷修为
- 散修 / 七玄门 / 黄枫谷 / 灵兽山在中后期仍有有效摘要与入口
- `help / codex / rumor / board / rank` 在中后期仍是核心信息系统

## 11. 实施建议

本设计适合当前仓库的原因：

- 不推翻现有骨架
- 直接扩现有 world/source、runtime、proto、client 结构
- 先做骨架，再做主路径，再做生态，返工风险最低

本设计完成后，项目将从“筑基初期版本”升级为“元婴初期可完整到达的共享世界修仙 MUD”。
